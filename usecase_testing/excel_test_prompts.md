# Excel MCP Test Prompts — Sales Dataset

## File: `sales_test.xlsx`

### Sheet structure
| Sheet | Description |
|---|---|
| `Sales_Data` | Raw data: ~240 rows × 12 columns (Order_ID, Date, Salesperson, Region, Category, Product, Quantity, Unit_Price, Discount_%, Revenue, Cost, Profit) |
| `Summary` | Dashboard: KPIs, revenue by category, by salesperson (with RANK), monthly trend + MoM growth |
| `Region_Category` | Crosstab: Revenue by Region × Category using SUMPRODUCT |

---

## TEST PROMPTS

### 🟢 LEVEL 1 — Read & Basic Aggregation

**E01.** What is the total revenue across all orders?

**E04.** Which product category has the highest total revenue?

**E05.** What is the average discount percentage applied to orders that had a discount?

**E09.** How many orders did "Alice" handle in total?

---

### 🟠 LEVEL 3 — Time-series & Trend

**E11.** Which month in 2024 had the highest revenue?

**E12.** Which month had the steepest month-over-month growth in revenue?

**E13.** What is the total profit for Q4 2024 (October–December)?

### 🔴 LEVEL 4 — Cross-dimension & Ranking

**E16.** Which Region × Category combination generates the most revenue?

**E17.** Which salesperson has the highest average revenue per order?

### 🟣 LEVEL 5 — Complex Reasoning

## PART 10 — EXCEL TO DATABASE UPLOAD

> **Context:** `sales_test.xlsx` → target DB has tables matching the e-commerce schema.
> Each prompt tests a distinct upload scenario or failure path.

---

### ✅ Happy Path — Basic Upload

**UPL01.** Upload the `Sales_Data` sheet from `sales_test.xlsx` into a new database table called `sales_raw`. Infer column names from row 1 and data types from the data.

**UPL02.** Upload only columns `Order_ID`, `Date`, `Salesperson`, `Region`, `Category`, `Product`, `Quantity`, `Revenue`, `Profit` from `Sales_Data` — skip `Unit_Price`, `Discount_%`, `Cost`.

**UPL03.** Upload the `Summary` sheet's monthly trend table (rows 14–25, columns A–D) into a table called `monthly_revenue`.

**UPL04.** Upload `Sales_Data` and map column names to snake_case DB columns: `Order_ID` → `order_id`, `Unit_Price` → `unit_price`, `Discount_%` → `discount_pct`, etc.

**UPL05.** Upload `Sales_Data` into an existing table `sales_raw` using INSERT — append new rows without truncating existing data.

**UPL06.** Upload `Sales_Data` into `sales_raw` using UPSERT: if `order_id` already exists, update the row; if not, insert it.

**UPL07.** Truncate the `sales_raw` table first, then re-upload all data from `Sales_Data` (replace mode).

---

### 🔁 Data Type Handling

**UPL08.** The `Date` column in the Excel sheet is stored as a string (`"2024-01-15"`). Upload it into a DB column of type `DATE` — verify the agent correctly parses and converts the format.

**UPL09.** The `Revenue`, `Cost`, and `Profit` columns contain decimal numbers. Upload them into `DECIMAL(12,2)` DB columns and verify no precision is lost.

**UPL10.** The `Quantity` column contains only integers. Upload it into an `INTEGER` DB column. Verify the agent rejects or flags the row if a non-integer value (e.g., `"5.5"`) appears in that column.

**UPL11.** Upload the `Discount_%` column (stored as a number like `10`, `15`) into a DB column named `discount_pct DECIMAL(5,2)` — verify no type mismatch.

**UPL12.** The Excel file has a `Date` column formatted as Excel serial number (e.g., `45321`) instead of a readable date string. Verify the agent correctly converts it to a proper date before inserting.

---

### ⚠️ Constraint Violation Paths — Expected to Fail or Warn

**UPL_ERR01. [Duplicate PK]** Upload `Sales_Data` twice into `sales_raw` (with `order_id` as primary key) using plain INSERT — verify the agent reports duplicate key errors for all rows on the second upload.

**UPL_ERR02. [NOT NULL violation]** Introduce a row in the Excel sheet with a blank `Product` cell (NOT NULL column) and upload — verify the agent catches and reports the null violation.

**UPL_ERR03. [Data type mismatch]** Put the string `"N/A"` in a `Revenue` cell and upload into a `DECIMAL` column — verify the agent returns a type conversion error for that row.

**UPL_ERR04. [FK violation]** Upload `order_items` data from Excel that references a `product_id` not present in the `products` table — verify the FK constraint is reported.

**UPL_ERR05. [Out-of-range value]** Include a row where `Discount_%` = 150 (violates CHECK 0–100) and upload — verify the CHECK constraint error is surfaced.

**UPL_ERR06. [Wrong column count]** Upload a sheet that has 10 columns but the target table expects 12 — verify the agent returns a schema mismatch error.

**UPL_ERR07. [Wrong column name]** Upload a sheet where a column is named `Rev` instead of `Revenue` — verify the agent either auto-maps, prompts for mapping, or reports an unrecognized column error.

**UPL_ERR08. [Empty sheet]** Upload a sheet that has headers in row 1 but no data rows — verify the agent handles gracefully (0 rows inserted, no crash).

---

### 🔀 Partial & Selective Upload

**UPL09b.** Upload only rows where `Region = "North"` from `Sales_Data` into a table called `sales_north`.

**UPL10b.** Upload only the top 50 rows (by Revenue) from `Sales_Data` into `sales_top50`.

**UPL11b.** Upload data from multiple sheets in one operation: `Sales_Data` → `sales_raw`, `Region_Category` → `region_crosstab`.

**UPL12b.** Skip rows that already exist in the target table (based on `order_id`) and only insert genuinely new rows — verify the agent reports how many rows were skipped vs inserted.

---

### 🔍 Post-Upload Verification

**VRF01.** After uploading `Sales_Data`, run a query to count the number of rows inserted and compare it with the row count in the Excel sheet — verify they match.

**VRF02.** After uploading, query the DB to find any rows where `Revenue` ≠ `Quantity × Unit_Price` (data integrity check).

**VRF03.** After uploading, verify that the `MIN(Date)` and `MAX(Date)` in the DB match the earliest and latest dates in the Excel sheet.

**VRF04.** After uploading with UPSERT (UPL06), re-upload the same file with 5 rows manually modified — verify exactly 5 rows were updated and the rest unchanged.

**VRF05.** After uploading, query total revenue from the DB and compare with the `Total Revenue` KPI in the `Summary` sheet — verify the values match.
